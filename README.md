# Skills for U｜核銷小幫手

單據拍照上傳 → 離線 OCR 辨識 → 人工確認 → 主管審核彙總 的小工具。對應技術規格文件的 **Phase 1（上傳介面 + OCR 辨識 + 手動確認分類）+ Phase 3（主管審核彙總介面）**。

## 如何開啟

這是純前端網頁，沒有後端伺服器，也不需要安裝、不需要 API Key。

1. 直接雙擊 `index.html` 用瀏覽器開啟，或
2. 在資料夾內開一個本機伺服器（建議，因為部分瀏覽器對 `file://` 開啟的頁面會限制本機儲存）：
   ```bash
   cd 單據辨識小幫手
   python3 -m http.server 8080
   ```
   然後瀏覽 `http://localhost:8080`。

手機請連到同一個區網位址（例如 `http://你的電腦IP:8080`），即可用手機相機直接拍照上傳。

## 部署到網路上給同事用

因為是純前端網頁，丟到任何靜態網站服務都能跑——Vercel、Netlify、Cloudflare Pages、GitHub Pages 都可以，選哪個都差不多：把 `index.html`／`style.css`／`app.js` 這三個檔案（`google-sync/` 資料夾不用上傳，那是給你貼進 Google Apps Script 的，跟前端網站無關）丟進去部署即可，不需要任何建置指令或環境變數。

**部署後有一件事要注意**：「雲端同步設定」（Apps Script 網址＋密碼）存在**每個人自己瀏覽器的 localStorage**，不會因為部署到公開網址就自動套用到所有訪客。也就是說同事打開你部署的網址，他的「雲端同步設定」預設是空的，不會自動連到你的 Google 試算表。

為了不用一個一個教同事貼網址密碼，「雲端同步設定」頁裡有「**產生給同事的一次性設定連結**」按鈕：

1. 你自己先把雲端同步設定好、測試連線成功、按過「儲存設定」。
2. 按「產生給同事的一次性設定連結」，把產生的連結複製起來。
3. 私訊或內部群組傳給要用的同事（**不要貼在公開頁面或大群組**，這串連結裡直接帶著密碼字串）。
4. 同事點開這個連結一次，瀏覽器會自動存好同步設定並跳出提示，網址列也會自動清掉參數，不會留密碼在瀏覽紀錄裡。之後他們開一般網址（不帶參數的）就會自動同步，不用再貼一次。

如果之後密碼字串換了（例如懷疑外流），舊的設定連結會失效，需要重新產生一份發給大家。

## 功能

- **上傳單據**：選上傳人、所屬專案，拍照或選檔案（JPG／PNG／PDF）。
- **OCR 辨識**：使用 [Tesseract.js](https://github.com/naptha/tesseract.js) 在瀏覽器內離線辨識繁體中文＋英文，自動抓取日期、金額、店家等欄位；也可改用雲端 OCR（Gemini）提高準確度並支援 PDF。
- **人工確認**：辨識結果一律先進確認表單，核對／補齊後才送出（信心分數偏低會醒目標示），並可標記「一般／緊急」。
- **上傳紀錄**：查看所有單據的上傳與審核狀態（唯讀），可依上傳人／專案篩選、匯出 CSV。按「🔄 重新整理審核狀態」會去問 Apps Script 拿總表上最新的審核結果並覆蓋本機顯示——因為實際審核發生在 Google 試算表，這個網頁本身不會自動知道結果，需要手動按一下才會同步過來。
- **名單設定**：顯示「上傳人」「所屬專案」下拉選單的內容。啟用雲端同步後，名單以 Google 試算表的「人員設定」「專案設定」分頁為準（所有人看到的一致），這頁改為唯讀檢視 + 一顆「從試算表重新抓取名單」；沒啟用雲端同步時才會退回成可在本機自行編輯的模式。

## 審核機制：權限控管在 Google 試算表

**審核動作不在這個網頁上進行**，而是在 Google 試算表裡。原因是：這個網頁的雲端同步是靠一組「大家共用的密碼」在運作，沒有辦法分辨誰是誰；如果把同意／退回按鈕留在網頁上，任何拿到設定連結的人都能核准，權限控管就形同虛設。所以審核搬到 Google 試算表，用 Sheets 原生的「受保護的範圍」做真正由 Google 強制執行的權限。

運作方式：

1. 單據送出後，除了寫進總表，也會自動複製一列到**該專案專屬的審核試算表**。
2. 每個專案的審核表只分享給該專案的審核人（編輯者），且表內除了「審核狀態／審核人／審核備註」三欄之外全部鎖定，所以審核人只能改審核結果，不能竄改單據原始資料。
3. 主管在審核表上把「審核狀態」改成「已核准」或「已退回」、選自己的名字、必要時填備註。
4. 總表每天晚上固定時間（預設 23 點左右）自動把各專案的審核結果同步回來（狀態／審核人／審核時間／退回原因）。這個排程只跑在 Google 的伺服器上，**電腦不用開著**。想馬上看到結果（例如緊急件），用總表選單的「立即同步審核結果」手動觸發即可。要改回更頻繁，改 `Code.gs` 裡 `setupTriggers()` 的 `.everyDays(1).atHour(23)` 這行（例如換成 `.everyMinutes(15)`，只能填 1/5/10/15/30）。
5. 同步時如果發現狀態是「已退回」，會把該筆憑證檔案**搬到主資料夾底下的「已退回」資料夾**，讓正式的專案／年月資料夾只留有效單據。檔案不會被刪除（退回常常只是金額打錯、用途沒寫清楚，之後還會用到同一張憑證，也保留稽核軌跡）。若主管後來改判為「已核准」，下次同步會自動把檔案搬回原本的專案／年月資料夾。

⚠️ Sheets 的保護只能限制「誰能編輯」，不能限制「誰能看到」。要讓專案之間互相看不到，靠的是**各專案審核表是獨立檔案、各自只分享給該專案的人**。所以請不要把這些審核表放進一個已經分享給全體同事的資料夾，否則所有人都會取得存取權。

⚠️ **檔案擁有者（不管是誰）永遠能編輯所有欄位，不受「受保護的範圍」限制**——這是 Google Sheets 平台本身的規則，不是這個系統的漏洞或設定沒做好。也就是說總表／審核表的擁有者就算不是某個專案的審核人，一樣能勾改任何欄位。想調整可以直接在 Sheets 介面手動管理保護範圍或共用權限，不需要改程式碼；但要注意重新執行選單「① 建立/更新設定與審核表」會依「專案設定」分頁的內容重建保護規則，把手動調整過的權限蓋回預設狀態。

專案與審核人的對照寫在總表的「**專案設定**」分頁（不是程式碼裡），人員或專案異動時直接編輯該分頁，再執行一次選單「① 建立/更新設定與審核表」即可，不用改程式碼也不用重新部署。

**已核准／未核准想要用顏色區分**：不用改程式碼，Google Sheets 內建的「條件式格式設定」就能做——選取「狀態」欄整欄 → 格式 → 條件式格式設定 → 規則設「文字完全符合『已核准』」上綠色、另一條規則「文字完全符合『已退回』」上紅色即可，設定完後自動套用到之後新增的每一列，不需要每次手動改。

## 人員與專案設定：改試算表，不改程式碼

第一次執行選單「① 建立/更新設定與審核表」時，總表會自動長出兩個設定分頁，之後**所有人員／專案異動都在這裡做**，不用改程式碼也不用重新部署：

**人員設定**：`姓名` ｜ `Email` ｜ `Slack個人ID`
- 姓名 → 上傳頁的「上傳人」下拉選單、組織匯款（組織人員）的「還款對象」選單
- Email → 對應到「專案設定」的審核人（決定審核表分享給誰）
- Slack個人ID → 緊急通知要 `@` 到人時用；不填就只顯示名字、不會推播

**專案設定**：`專案名稱` ｜ `審核人Email（逗號分隔）` ｜ `狀態` ｜ `憑證資料夾ID` ｜ `審核表ID` ｜ `審核表連結`
- 狀態填 `進行中` 或 `已結束`
- 審核表ID／連結是系統自動填的，**不要手動改**（靠 ID 找檔案，所以你把審核表搬到別的資料夾也不會壞）

**新增專案**：在「專案設定」加一列 → 執行選單「① 建立/更新設定與審核表」→ 系統自動建立該專案的審核表、設好權限、分享給審核人。

**專案結束**：把「狀態」改成 `已結束`。之後該專案不會出現在上傳選單、不會出現在 Slack 審核日提醒、也不會再建立新的審核列，但**審核表與歷史資料都完整保留**（稽核用），不會被刪除。要歸檔的話再自行把審核表搬到你想放的資料夾即可。

⚠️ **為什麼要搬到試算表**：先前名單存在每個人自己的瀏覽器（localStorage），會有兩個問題——你新增的專案只有你看得到、別人看到的是舊名單；而且如果專案沒同時寫進程式碼的審核人設定，單據上傳後會**靜靜地不建立審核列**，主管永遠看不到那張單據。改成試算表為單一真相來源後這兩個問題都消失了，而且現在遇到「專案不在設定分頁」會明確記錄錯誤而不是沉默略過。

## Slack 通知

在 `Code.gs` 填入 `SLACK_WEBHOOK_URL` 後啟用（留空則完全不發送，不影響其他功能）。申請方式：Slack → 你的工作區 → Apps → 搜尋「Incoming Webhooks」→ 選一個頻道 → 複製網址。

- **緊急件**：上傳者在確認表單上選「緊急」，送出當下立刻發一則 Slack 訊息，**真的 `@` 到該專案審核人**（會跳出通知），帶上專案、金額、用途、憑證連結與審核表連結。
- **一般件**：不即時打擾，改由每月固定的審核日提醒 —— 預設每月 10 號上午 10 點，不管當下有沒有待審項目，一律用 `<!channel>` 發一句「今天是各位主管的審核日，請記得審核喔！」（等同 Slack 的「@all」），並附上每個進行中專案審核表的連結。**如果 10 號剛好是週六或週日，會自動順延到下一個週一發送**（判斷邏輯在 `isReviewReminderDay_()`），順延後仍會落在 13 號前，符合 10–13 號的審核區間。要改文字內容改 `sendPendingDigestToSlack`；要改日期改 `DIGEST_DAY_OF_MONTH` 後重新執行選單「② 設定自動排程」。
- **付款完成通知**：**不排程**，由會計在總表填完付款日期後，自己從選單按「💰 立即發送付款通知到 Slack」。因為會計是排班制、不一定在款項發出當天上班，固定排程反而容易錯過。訊息會用 `<!channel>` 報「本月已完成付款 X 筆，合計 NT$ Y」並依專案列出明細。
- **缺件退回通知**：主管在審核表把「審核狀態」改成「已退回」後**約 20 秒**發出（不是排程等待，是刻意留一段緩衝——大部分人會先選狀態、才回頭在旁邊打退回原因，抓太快原因欄常常還是空的；`REJECT_NOTIFY_DELAY_MS` 可調），**真的 `@` 到申請人本人**，帶上專案、發票日期、金額、內容、以及主管填的退回原因。這個通知跟總表的每日同步是分開的機制（見下方 ⚠️），不用等排程或手動同步。目前設計是「只通知申請人」，不處理同一筆被退回多次要不要疊加提醒、也不做「退回超過幾天還沒補件」的二次催促，這兩個之後有需要再加。

**緊急通知、缺件退回通知要真的 tag 到人，都要在總表「人員設定」分頁填上 Slack 個人 ID**。抓法：Slack 點開那個人的個人檔案卡片 →「⋯ 更多」→「複製會員 ID」。沒填的人，訊息裡只會顯示他的名字（純文字），不會真的推播通知給他。

⚠️ **「缺件退回通知」是即時的，但「總表看到的審核狀態」不是。** 主管按下退回的當下，Slack 通知立刻發出去，但收支總表要等每天固定的排程（或手動點選單「立即同步審核結果」）才會顯示「已退回」。這是刻意分開的兩件事：即時通知靠的是另外裝在**每份審核表上**的觸發條件（`onReviewStatusEdit_`，第一次執行選單「① 建立/更新設定與審核表」時會自動裝上，之後每次重跑這個選單都會確認已經裝著、不會重複裝），不是靠總表的每日同步；如果需要總表也做到即時，要另外評估，目前沒有做。

⚠️ 如果你用的是**私人頻道**，`@` 提及只對「本來就是這個頻道成員」的人有效——對方要先被邀進頻道，才會被通知到；不在頻道裡的人，就算填了 Slack ID 也不會收到任何東西。

## 資料存放

所有紀錄（含單據縮圖）預設存在瀏覽器的 `localStorage`，只存在你目前這台電腦、這個瀏覽器裡，重灌瀏覽器或清除瀏覽資料會遺失。如果你設定了下面的「雲端同步」，資料會**同時**寫進 Google 試算表與 Drive，本機 localStorage 則作為離線暫存／備援。沒設定雲端同步的話，就用**匯出 CSV** 取代自動寫入雲端試算表，用**下載重新命名後的檔案**取代自動歸檔至 Google Drive。

⚠️ **localStorage 通常只有 5~10MB，憑證照片的 base64 內容很佔空間，用一陣子容易爆滿**——爆滿時瀏覽器會直接丟出錯誤，如果沒特別處理，會讓「送出審核」看起來像完全沒反應（按鈕點了卻沒有任何提示）。系統已經處理了這個狀況：一筆紀錄成功同步到雲端之後，會**自動清除該筆的本機縮圖**（Drive 上已經有正本，本機縮圖只是上傳前的暫存，不需要留著），平常用不太會真的爆滿；萬一還是遇到，送出時會自動先清掉其他已同步紀錄的縮圖騰出空間再重試，並且**一定會用提示文字告訴你發生了什麼事**（例如「已自動清理部分舊縮圖騰出空間」），不會再默默失敗。已經清除縮圖的紀錄，在「上傳紀錄」的詳情視窗裡會改成顯示「查看雲端檔案」連結。

## 雲端同步：接到 Google 試算表 / Drive

工具內建了一個「雲端同步設定」頁面，可以連到你自己部署的 Google Apps Script，之後每次上傳、主管審核，都會自動：
- 把單據資料寫成一列，加進你指定的 Google 試算表分頁。
- 把單據照片存進你指定的 Google Drive 資料夾（或自動建立一個叫「核銷小幫手」的資料夾）。
- 主管同意／退回時，回頭更新試算表裡對應那一列的狀態、審核人、審核時間、退回原因。

設定步驟：

1. 開一個 Google 試算表（或用現有的收支表）。
2. 選單「擴充功能」→「Apps Script」，把本資料夾裡 [`google-sync/Code.gs`](google-sync/Code.gs) 的內容整份貼進去，覆蓋原本內容。
3. 把程式碼裡的 `SECRET_TOKEN` 改成你自己的一串密碼（英數字，越隨機越好）；需要的話也可以調整 `SHEET_NAME`（寫入哪個分頁）與 `DRIVE_FOLDER_ID`（憑證存到哪個資料夾，留空會自動建立）。
4. 右上角「部署」→「新增部署作業」→類型選「網頁應用程式」：執行身分選「我」，誰可以存取選「任何人」。部署後會拿到一個網址（結尾 `/exec`）。
5. 回到核銷小幫手網頁，切到「雲端同步設定」頁：貼上網址與你剛設定的密碼字串，按「測試連線」確認成功，勾選「啟用雲端同步」，再按「儲存設定」。

**安全性提醒**：「誰可以存取：任何人」代表這個網址是公開的，任何人拿到網址＋正確密碼就能寫資料進你的試算表/雲端硬碟。請不要公開分享這個網址與密碼；如果不小心外流，回 Apps Script 改一個新密碼、重新部署即可讓舊的存取失效。之所以選這個方式而不是正規 OAuth 串接，是因為 OAuth 需要每個上傳單據的人都用自己的 Google 帳號登入授權，設定複雜、也不符合「很多人隨手上傳」的情境；Apps Script 方式則是你（試算表擁有者）設定一次，其他人不需要登入 Google 帳號。

### 收支表欄位順序

寫入試算表的欄位、順序固定如下（`紀錄ID` 放最後一欄，是給 `updateRow_` 找列用的，主管審核同意/退回時要靠它回頭更新狀態，不建議刪除整欄）：

| # | 欄位 | 說明 |
|---|------|------|
| 1 | 上傳時間 | 換算成 GMT+8、精確到分鐘，例如 `2026-07-31 14:23` |
| 2 | 上傳者 | |
| 3 | 所屬專案 | |
| 4 | 發票日期 | |
| 5 | 金額 | |
| 6 | 單據內容 | |
| 7 | 公司名稱 | |
| 8 | 用途 | |
| 9 | 所屬期間 | 依發票日期自動判斷的「年-月」 |

### 付款資訊：讓財務看總表就能直接付款

「上傳人」和「收款對象」是兩件事——常有「我幫同事送單、但要還款給同事」的情況，所以收款對象是獨立欄位，不是從上傳人推導出來的。上傳表單依「付款方式」決定要填什麼：

| 付款方式 | 要填的資訊 |
|---|---|
| 組織匯款（組織人員） | 還款對象（下拉選單，預設帶入上傳人，**可以改成別人**） |
| 組織匯款（非組織人員） | 戶名 + 帳號資訊（銀行、分行、帳號，欄位下方附填寫範本提示） |
| 組織零用金 | 不用填，款項已由組織當場支付 |
| 組織信用卡（連結） | 對方提供的線上刷卡連結 |
| 組織信用卡（紙本） | 不用填卡號（卡號由偉翔另外提供），只需兩項必勾確認：「我已確認對方無法使用匯款付款」「我已確認對方無法提供線上刷卡連結」——兩項都勾選才能送出，避免優先順序被略過（能匯款/線上刷卡就不要用實體卡） |

組織匯款（組織人員）刻意不要求填銀行帳戶，因為財務手上已有同仁帳戶資料，避免帳戶這種敏感資訊重複散落在試算表跟瀏覽器裡。這幾個欄位也會出現在各專案審核表上，讓主管核准時知道自己批准的是哪一種付款。

### 期望撥款日期

組織固定在每月 5 號、20 號撥款，系統會依「送出審核當下的日期」（不是發票日期）自動推算：

| 付款方式 | 9 號（含）前送出 | 9 號後送出 |
|---|---|---|
| 組織匯款（非組織人員）／廠商款項 | 當月 20 號 | 次月 20 號 |
| 組織匯款（組織人員）／同仁代墊 | 次月 5 號 | 次次月 5 號 |

其他付款方式（零用金／信用卡）沒有固定發款週期，不自動推算，「期望撥款日期」欄位留空。

標記「緊急」時不套用上面的公式，改由上傳人自己在「希望完成付款日期」欄位選一個日期，因為緊急案件的迫切程度只有申請人自己清楚。無論哪種情況，審核通過後系統都**不會另外推播通知**——會直接把「已收到您的審核，請於 X 月 X 日前繳交憑證至後勤人員處」這行提醒顯示在「上傳紀錄」頁該筆紀錄卡片上，等到後勤人員在總表把「單據完備」勾起來，這行提醒就會自動消失。

計算邏輯在 `app.js` 的 `computeExpectedPayoutDate`，只根據目前明確確認過的「9 號前」規則往兩個方向推算（廠商款項當月 20 號、同仁代墊次月 5 號），「9 號之後送出」怎麼算是依照同樣週期邏輯自然延伸出來的，如果跟實際財務作業對不上，請直接告知調整。

### 急迫性：只有零用金沒有

規則刻意維持成**一個例外**，而不是一套分類，這樣同事只要記一句話：

> 除了組織零用金以外，都可以標記緊急。

| 付款方式 | 急迫性切換 |
|---|---|
| 組織零用金 | ❌ 整塊隱藏，固定為「一般」 |
| 其他四種 | ✅ 顯示，勾緊急後填「希望完成付款日期」 |

零用金隱藏的理由是**結構性**的：款項固定、而且進到系統時早就以現金支出，催主管不會改變任何事。

信用卡曾經考慮一起隱藏（多數情況也是刷完才建檔，例如採購 Apple 電腦是先刷卡、拿到發票後才進系統請款），最後決定**保留**，理由是猜錯的代價不對稱：多留一個用不到的開關，使用者用個幾次自然就不會再點；但少留一個其實需要的開關，當事人完全沒有替代方案，只能改程式碼才救得回來。在證據不足的情況下（實際案例只有兩筆，其中一筆最後還改成匯款），選那個錯了比較好救的。

「希望完成付款日期」的標題刻意用通用說法，讓匯款（撥款）與信用卡（刷卡）共用同一個欄位，不依付款方式換字——這是**減少**一條分支，不是增加。

實作在 `app.js` 的 `methodAllowsUrgency_()` 與 `updateUrgencyVisibility()`。切換到零用金時會順手清掉已勾選的「緊急」與已填的日期，`submitRecord()` 裡也再擋一次（`methodAllowsUrgency_(payMethod) && currentUrgent`），確保不會送出「畫面上看不到緊急、資料裡卻標著緊急」的紀錄。

### Drive 資料夾與檔名規則

憑證照片存進 Google Drive 時，會先依「專案」分資料夾，資料夾裡再依「所屬期間」分月：

```
核銷小幫手（主資料夾，或你設定的 DRIVE_FOLDER_ID）
├── 組織發展中心
│   └── 202607
│       ├── 20260715_64元.jpg
│       └── 20260720_1500元.pdf
├── 高雄技職年會
│   └── 202607
│       └── ...
```

檔名是「年月日_金額」（例如 `20260806_125元`），不重複標專案跟年月資料夾名稱裡已有的部分（那是刻意的：資料夾路徑已經知道是哪個專案、哪個月，檔名裡再放一次年月沒有增加資訊；但保留完整日期是為了同一個月份、同一個資料夾內多筆單據時，光看檔名就能分辨是哪一天）。這個規則同時決定了「上傳紀錄」單據詳情裡「下載憑證檔案」按鈕產生的檔名。要調整規則的話：資料夾邏輯在 `Code.gs` 的 `getProjectFolder_`／`getMonthFolder_`，檔名邏輯在 `app.js` 的 `suggestFileName`，兩處要一起改才會維持一致。

**專案資料夾可以指定用現成的**：在總表「專案設定」分頁的「憑證資料夾ID」欄留空，會自動在主資料夾底下建立同名資料夾；填入現成資料夾的 ID（開啟資料夾看網址列 `.../folders/『這一串』`），就會直接存進你指定的位置，不會另外新建。

## 雲端 OCR：用 Gemini 取代離線辨識

預設的 OCR 是瀏覽器內建的 Tesseract.js，完全離線、免費，但遇到模糊、反光、手寫的單據辨識率會明顯下降。如果想要更準的辨識，可以讓「上傳單據」頁的「開始辨識」改成呼叫 Gemini（透過你已經部署的同一個 Apps Script，不需要另外架伺服器）：

1. 到 [Google AI Studio](https://aistudio.google.com/apikey) 用同一個 Google 帳號申請一組 Gemini API 金鑰（有免費額度）。
2. 回到 Apps Script 編輯器，把 `Code.gs` 裡的 `GEMINI_API_KEY` 改成你申請到的金鑰，存檔。
3. 「部署」→「管理部署作業」→ 編輯（鉛筆圖示）→ 版本選「新版本」→ 部署，讓程式碼改動生效（網址通常不會變）。
4. 回到核銷小幫手的「雲端同步設定」頁，勾選「使用雲端 OCR」，按「儲存設定」。

啟用後，「開始辨識」會先呼叫 Gemini；如果雲端辨識失敗（額度用完、網路問題等），會自動退回本機離線辨識，不會卡住讓你上傳不了單據。Gemini API 金鑰跟 `SECRET_TOKEN` 一樣是敏感資訊，不要把 `Code.gs` 或部署網址分享出去。

**PDF 檔案只能用雲端 OCR**：Tesseract.js（離線辨識）只能讀圖片，沒辦法處理 PDF，所以上傳 PDF 時，如果沒開啟雲端 OCR，會直接跳到手動輸入欄位、不會嘗試辨識。開啟雲端 OCR 之後，PDF 會自動判讀日期、金額等欄位讓你確認。

**PDF 辨識加速**：PDF 整份原始檔案直接送給 Gemini 常常偏大、拖慢辨識速度，所以會先在瀏覽器裡用 [pdf.js](https://mozilla.github.io/pdf.js/) 把 PDF 轉成最多前 3 頁的壓縮圖片再送出辨識（存進 Google Drive 的仍是原始 PDF，不受影響）。如果轉檔逾時或失敗（例如瀏覽器分頁被背景節流），會自動退回直接送整份原始 PDF，不影響辨識能不能成功，只是速度差一點。雲端 OCR 本身也加了 45 秒逾時，超過就自動判定失敗、退回本機離線辨識，不會無上限空等。

### 設定雲端 OCR 時的常見卡關（實際踩過的坑）

**1. 出現「你沒有呼叫『UrlFetchApp.fetch』的權限」**
新增 Gemini 功能後，Apps Script 多需要一個「對外連線」權限，要重新授權才會生效：

- 先確認 `appsscript.json` 裡有 `oauthScopes`，且包含 `https://www.googleapis.com/auth/script.external_request`（若編輯器看不到這個檔案，到左側⚙️專案設定勾選「在編輯器中顯示 appsscript.json」）。
- 然後在編輯器上方函式下拉選單選 **`testGeminiAuth`** → 執行 → 走完授權流程（進階 →「前往…(不安全)」→ 允許）。
- ⚠️ **函式名稱結尾不能有底線**：Apps Script 會把 `xxx_()` 視為私有函式，**不會顯示在下拉選單裡**，所以 `recognizeReceipt_` 這類函式無法直接執行，必須透過 `testGeminiAuth` 這種沒有底線的函式來觸發授權。

**2. 出現 429（quota exceeded）**
代表這個模型在你的帳號沒有可用額度。到 <https://ai.dev/rate-limit> 查，顯示 `0 / 0` 的模型不能用，要挑後面數字不是 0 的；`Flash TTS` 系列是語音用的，不能辨識單據。數字若標示 per minute，是「每分鐘」上限、每分鐘會重置。

**3. 出現 404「no longer available to new users」**
該模型已被 Google 淘汰。建議直接用 `gemini-flash-latest` 這個別名（本專案的預設值），它會自動指向最新的 Flash 模型，不會因為版本淘汰而失效。

**4. 編輯器測試成功，但網頁版還是報錯**
代表**部署的版本還在跑舊程式碼**。改完 `Code.gs` 一定要重新部署才會生效：「部署」→「管理部署作業」→ 編輯 → **版本要選「新版本」**（保持原版本號等於沒更新）。如果反覆失敗，直接「新增部署作業」建一個全新的，再把新網址貼回工具的「雲端同步設定」並**按儲存設定**。

驗證方法：在「雲端同步設定」按「**測試連線**」，訊息會顯示這個部署實際使用的 OCR 模型。若顯示「這個部署版本較舊，沒有回報模型資訊」，就是部署沒更新到。

## 已知限制（對應原始文件中「尚待釐清」的項目）

- **會計科目分類規則**：目前只有幾條示範性的關鍵字對照（辦公用品／交通費／餐費等），正式的「會計科目 ↔ 預算項目 ↔ 專案」對照表尚未由財務盤點確認，屬於組織治理決策，不是工程可以自己生成的（技術規格文件第 4.2、8 節）。
- **通知機制**：規格書提到要通知主管有新項目待審、退回要通知申請人，但目前沒有後端可以寄信或推播，所以只用畫面上的角標數字／狀態呈現。
- **OCR 準確度**：離線辨識（Tesseract.js）對印刷體發票效果通常不錯，但手寫、模糊、反光的單據辨識率會明顯下降；雲端 OCR（Gemini）效果較好但需要額外設定 API 金鑰、且有網路才能用。不管哪一種，每筆都設計成「AI 建議、人工確認後才送出」，不會自動寫入未經確認的資料。
- **多人協作**：因為資料在瀏覽器本機，目前無法多人即時共用同一份清單；若要多人共用需要接後端資料庫（或都設定同一組雲端同步，彼此在 Google 試算表裡看彙總）。
